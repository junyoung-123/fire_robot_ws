## R34 입력과 수치
- 손잡이: primary YOLO + registered RGB-D. 문 후보에는 HSV fallback 사용 가능.
- 문 각도: RGB-D 문 평면 + 2D LiDAR 패널 관측. 엔코더만으로 문 각도를 만들어 쓰지 않음.
- 레버: 강체 파지 가정하에 로봇 엔코더 FK로 추정. 직접 레버 센서·토크 측정이 아니며 미끄러짐 완전 증명 아님.
- 제어 입력 감사는 문/레버 관절 정답·model/link pose 구독 금지 조건 통과. 로봇 TF/엔코더는 시뮬레이션 센서.
- 개방 확인: 관측 117.776도 / 평가 정답 117.839도. 움직이는 구간 RMSE 0.343도.
- 목표 개방각·누름 방향·안전 한계·접근 여유는 설정값으로 남음. '하드코딩 0' 표현 금지.
- 문/레버 시뮬레이터 정답 및 contact pair는 독립 checker가 평가에만 사용.
- 제어 소스는 당시 snapshot과 일치. 09-26 추가 확인은 문법·단위 테스트이며 새 Gazebo 성공이 아님.

## 그림을 해석할 때
- W*_combined의 벽·문·장애물 도형은 SDF 정답 배치. 선은 기록된 로봇 중심 경로. 임의 평활화/좌표 맞춤 없음.
- W*_combined의 문은 초기 닫힌 위치. 시간에 따른 문 회전이나 차체 전체 clearance는 별도 검증 대상.
- Q1/Q2의 배경 /map은 고정이며 문 랜드마크만 갱신. 카메라 최근 수신과 FSM 기록의 짝이지 완전 노출 동기화 보증 아님.
- OV1 bbox는 같은 실행의 저장 검출 출력. 원본 검출 timestamp가 없어 엄밀한 센서 동기화는 보증하지 않음.
- P_blue 장애물 Door0.27은 오탐. P1_camera는 카메라 수신 대기 화면. PV1은 시점·가림 문제. 세 자료는 성공 예시가 아님.

## 실제 사진 평가
실제 validation 이미지와 정답 라벨은 현재 전달 자료에 없음. 팀원의 기존 요약은 원본 참고로만 보존하며 자체 재평가 수치로 쓰지 않음. Gazebo 레버 성능을 실제 사진 수치로 대체하지 않음.
