## 이전 시험과의 차이

| 구분 | 2026-09-16 주행 기록 | 2026-09-29 r29 |
|---|---|---|
| 지도 | 저장 지도 | 매번 새 온라인 SLAM |
| 주행 위치추정 | 시뮬레이션 odometry | 휠 odometry + LiDAR SLAM |
| 사전 문·장애물 배치 | 저장 지도의 기하 정보 포함 | 제어 입력에서 제외 |
| 문 처리 | 단순 힌지 backend | 방문 완료 어댑터, 물리 개방 없음 |
| 출구 | 이전 초록 패널 | 초록 표식이 있는 열린 통로 |
| 문 기억 | 위치·완료 상태 기억 | 유지, 관측 좌표 갱신 전후의 선택 후보 연결 보강 |

카메라 관측으로 문·색상 후보를 누적합니다. 시뮬레이터 정답 위치와 월드 배치는
수집·사후 평가에만 사용합니다. 169회 입력 감사에서 계약 위반은 없었습니다.
센서 보정값, 안전 거리, 병합 허용오차와 문 높이 기반 보조 추정은 남아 있으므로
"모든 설정값 제거" 또는 "하드코딩 0"이라는 의미는 아닙니다.

## 성공 기준과 남은 한계

- 문 중심 진행축 오차 0.70 m 이내, 방문 거리 1.60 m 이내, 벽면 정면 방향 오차 15도 이내.
- 전체 파란 문 중복 없이 유효 방문, 빨간 문 방문 없음, 실제 출구 통과.
- 기록된 Nav2 외곽선의 장애물·벽·문 패널 겹침 없음. 접촉 센서 기반 충돌 시험은 아닙니다.
- 최대 위치추정 오차는 월드별 약 0.52~0.79 m. W3 재접근과 W4 긴 회피 재시도는 미해결 품질 한계입니다.
- 로봇팔 도달 거리, 문 바로 앞 정밀 주차, 다문 물리 개방, 새 코드의 스트레스·반복 성공률은 검증하지 않았습니다.
- R34 단일문 센서 기반 접촉 개방은 별도 결과입니다. 두 성공을 하나의 다문 통합 성공으로 합치지 않습니다.

## 코드와 기록 일치

게시 시 실행 소스 89개, 기록된 검증 파일 10개를 다섯 실행의 SHA256과 비교해
모두 일치함을 확인했습니다. 관련 회귀 테스트는 게시 전 재실행하여 96개 PASS입니다.
기존 전체 빌드 7개 패키지 및 당시의 회귀 62개 PASS 기록과 구분합니다.
게시 작업 자체는 새 Gazebo 실행이 아닙니다.

pytest 자동 플러그인 로딩 시 사용자 설치 anyio와 시스템 pytest의 버전 충돌이 있어
`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`로 무관한 외부 플러그인을 제외했습니다.
WSL setup에는 이번 주행 빌드에서 제외한 `fire_robot_sim_evidence`의 오래된 경로 경고가
남지만, ROS 환경에서 선택한 96개 시험은 모두 수집·실행되었습니다.
